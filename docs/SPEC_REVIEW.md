# 规范审核 · 2026-09-28

## 本阶段范围与事实

仅优化规范及与范围相关的校验规则，不搭建主站、不导入工具、不连接或推送 GitHub。本次初始审核时目录不是 Git 仓库；当时无 site、tools、构建脚本或 Pages workflow，tools.json 为空。现有 CI 配置只是待接入的文件，不代表远端已经运行。

## 已消除的歧义

- 首版直接列出全部工具，不做分类侧栏、搜索和筛选；展开指展示入口，不同时运行所有工具。
- category 不再必填，标签可为空；校验器同步取消分类限制。
- 每次 push 都先风险检查再正式确认；开发分支推送不包含合并与上线许可。
- 功能分支、PR、稳定标签与版本记录分别承担开发、审核、识别和追溯；回退形成新提交与新版本。
- main 合并与上线分开；未来仅从已批准版本标签部署。当前未实现此部署工作流。
- draft 不进入站点但在公开仓库里仍公开；published 表示构建资格，不表示已经上线。
- 导入时先补齐 draft 元数据再校验，避免缺失元数据导致步骤互相冲突。
- 旧身份清理不得删除法定或许可要求的第三方声明；存在冲突时阻断导入。

## 工程限制与下一阶段检查

现有 verify 在严格模式下加载仓库外私有规则并做基础结构检查，公开 CI 只做结构检查，不是完整安全审计。尚不能自动验证 HTML/CSS/JS 中的所有资源引用、跨工具依赖、权限需求、外部网络行为、真实日期和全部可选字段；这些仍需人工复核，首个工具接入时按实际需求加强。尤其不能把内容扫描通过等同于没有密钥或个人信息。

用户确认目前靠工作约定执行，脚本无法辨认聊天授权。远端分支保护、必需检查和发布权限尚未设置，首次接入时需要核实并落地。现有 validate workflow 仅检查通用结构，不接收私有规则；主站实现阶段需补齐构建验证、产物边界验证、标签部署及回退演练。

发布记录目录在第一个稳定版本准备时创建，不为尚未提交的规范虚构版本、SHA 或 Release。无 Git 阶段使用文件差异审阅；历史与 Git diff 检查待初始化后补齐。

## 追加审核：规则自身的公开风险

已移除源码中的内置编码词库，规则本身同样受公开内容政策约束。完整检查必须加载仓库外非空词库；通用结构检查明确不提供内容审查结论。诊断不输出文件路径、规则或命中原文。默认词库不上传 GitHub；远端 CI 绿色不能代替本地私有检查。

本机已按用户指定范围在仓库外配置持久私有词库，检查器自动读取用户级默认配置，也允许环境变量覆盖。词库不随项目分发，其他机器需独立配置；后续由用户指定规则更新。合成测试只能验证机制，真实检查仅覆盖当前词库，不能证明所有内容安全。
