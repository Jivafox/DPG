# 内容与仓库清理政策

## 发布前门槛

仓库只使用 DPG 或与工具功能相关的中性身份。每次导入与提交前检查品牌、组织名、项目名、内部链接、个人信息、密钥、许可证和素材来源。规则、规范、检查脚本也属于待公开内容，不能享有扫描豁免。

## 公开原则与私有规则

公开仓库只保存通用政策、扫描逻辑及不含真实规则的合成测试。具体禁用词、敏感模式及其来源说明必须保存在仓库外；禁止写进文档、配置、测试、注释、提交信息、PR、Release、截图或日志。数字字节、转义、Base64、拆分字符串等可还原表示同样属于规则泄露，不能用编码代替隔离。不发布敏感词的哈希或其他可用于猜测词库的指纹。

默认从当前用户主目录下的 `.config/dpg/guard.txt` 自动读取；可用环境变量 `DPG_GUARD_FILE` 指定其他仓库外的 UTF-8 私有文件（显式指定无效路径时失败，不回退默认文件）。该文件每行一条字面子串匹配规则，英文字母不区分大小写，中文按原文匹配，空行忽略，不支持正则或注释语法。环境中只设置路径，不把词库粘贴到命令行。文件采用仅本人可读写的权限，置于稳定的私有位置；不放进工作树、构建目录、云同步或待打包目录。`.gitignore` 不能替代物理隔离，历史中出现过的规则仍须按事故流程处理。

默认采用本地私有检查，不将词库上传 GitHub，包括 Actions Secret、缓存和构建产物。未来确有远端私有检查需求时，须先解释规则会传到远端并取得专项授权，单独设计受信任执行与日志策略；不能给不受信任的 PR 代码提供词库。

本地输出也按可能被公开处理：不打印命中原文、具体规则、敏感路径、私有规则路径或原始异常。排查在本地私有环境中完成，对外只记录检查类型、结果与被检查 commit，不附词库内容或指纹。词库完整性需要人工确认，非空不等于覆盖完整。

## 两种检查模式

- `node scripts/verify.mjs --structure-only`：通用结构检查，不加载私有词库；可用于日常规范编辑和公开 CI，成功不代表私有内容审查通过。
- `node scripts/verify.mjs`：完整工作树检查，必须存在默认私有文件或通过 `DPG_GUARD_FILE` 指定有效私有文件。缺失、空白、不可读或真实路径位于仓库内时失败；不自动降级。
- `node scripts/verify.mjs --history`：完整工作树及可达 Git 历史检查，同样要求私有词库及有效 Git 仓库。提交后、每次 push 前执行，并审阅实际拟推送内容。

完整检查失败时不得提交、推送或发布。没有私有配置时可继续本地编辑及通用结构检查，但必须明确记录完整内容检查未完成，不能用通用检查替代准入检查。仓库只保留接入说明，不附真实词库示例。

## 检查范围

校验器扫描仓库可见的文件名、目录名和文件内容（包括通常的文本与二进制原始字节），排除 `.git` 和生成/依赖目录。公开 CI 只做通用结构检查，不加载词库、不做私有历史扫描。生成产物不在源码扫描范围内，打包或发布前须另外人工检查产物和资源；不能把源码检查当作产物审核。人工复核图片中的文字、图层、音视频、压缩内容和脚本动态生成内容；程序扫描不等于完整的版权或泄密审核。外部 CDN、网络响应和第三方资源也要核查。

## 修正原则

可见文案、标题、alt、meta、注释、普通变量及资源名按语义清理，修复引用并验证功能。协议字段、依赖 API、文件格式或许可证不能任意改写；有风险则暂缓导入。不要用大小写变化、编码或字符串拼接规避规则。不得将检测规则或被拦截原文记录在公开日志中。

## 历史与事故处理

新仓库首次发布前运行 `node scripts/verify.mjs --history` 核查可达 Git 历史；正常情况下先在仓库外清理原件，再移入并暂存。若敏感内容已提交但未推送，停止推送，评估本地历史修复；若已推送，停止发布并评估撤销、密钥轮换、历史清理与协作者同步。普通 revert 不能删除公开历史中的原文。共享仓库历史处理需协调所有协作者，不能擅自强推。历史扫描覆盖当前可达 Git 对象；已删除的远端引用或其他副本仍需单独核查。

## 门禁

本地提交前运行完整检查（现有 pre-commit 使用默认严格模式），公开 CI 运行 `node scripts/verify.mjs --structure-only`。脚本失败时不得提交、合并或发布。Git hook 只是便捷提醒，可能被绕过；受保护分支需将 CI 设为 required check。远端规则由仓库管理员配置，文档本身无法自动启用。

## 公开边界与许可

工具状态只决定是否进入站点产物，不隐藏公开 Git 仓库中的源码、文档、分支或历史。首次推送与后续推送均须审查本次新增公开的文件及提交。自动内容扫描只覆盖实际加载的私有规则，不能证明没有密钥、个人信息或未知敏感内容，人工风险检查不可省略。

清理旧身份不能删除第三方许可要求保留的版权、署名或许可证。允许合规依赖的必要声明；若必要声明与禁用内容冲突，停止导入并说明冲突，不通过改名或删声明规避。推送、合并和部署授权按 `GITHUB_WORKFLOW.md` 执行。
