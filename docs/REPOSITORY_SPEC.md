# DPG 仓库蓝图

## 目标与边界

DPG 是公开可用的个人工具工作空间。每个工具由独立 HTML 入口与本地资源组成；主站提供浏览、说明和站内运行容器。V1 无站内上传、账户、数据库或服务端。部署源为 GitHub 仓库，发布渠道为 GitHub Pages。

## 目录归属

```text
DPG/
├─ AGENTS.md
├─ README.md
├─ docs/                    # 规范与协作说明，不是 Pages 输出
├─ scripts/                 # 本地/CI 校验与后续构建脚本
├─ .github/workflows/       # 校验与后续发布
├─ site/                    # 主站页面、样式、脚本、资源
├─ tools/                   # 每工具一个独立目录
│  └─ <slug>/
│     ├─ index.html
│     ├─ tool.json
│     └─ assets/
├─ tools.json               # 唯一公开索引，发布工具的有序 slug 列表
└─ dist/                    # 生成物，忽略，不作为源文件
```

`site/`、`tools/`、`docs/`、`scripts/` 各自独立。主站不得直接加载工具样式或脚本；工具不能依赖主站 DOM、CSS 或内部 API。工具原生页面是完整体验，站内 iframe 是嵌入体验。外部依赖优先固定版本并确认许可和 Pages 可用性。

## 路由与构建契约

- Pages 项目站点通常部署于 `/<repo>/` 子路径；所有导航、资源及 iframe 地址应基于当前站点根路径生成，不写 `/tools/...` 等域名根路径。未来自定义域名也须在根路径下工作。
- 建议构建脚本从 `site/` 拷贝至 `dist/` 根，将已发布工具目录拷贝至 `dist/tools/<slug>/`；根目录生成 `index.html` 和 `.nojekyll`。不要把 `docs/`、源图或未发布工具复制到输出。
- `tools.json` 是有序 slug 数组：`{"published":["example-tool"]}`；工具详细信息以各自 `tool.json` 为唯一来源。构建时读取并生成 `dist/catalog.json`；浏览器只读构建产物，不尝试静态枚举文件夹。
- `draft`、`review`、`ready` 工具只存在源目录，不进入 `dist/`；`published` 必须在索引中且通过校验。下架时先从索引移除，核对外部链接与构建产物。
- 浏览器打开 `<site-base>/tools/<slug>/index.html` 应独立可用。站内 iframe 提供标题、返回、独立打开按钮；如果工具需要相机、剪贴板或下载权限，逐项测试嵌入态。不要默认使用会阻断脚本或同源功能的 iframe sandbox 属性。
- V1 主站使用原生 HTML/CSS/JS，Node 22 仅用于校验、静态构建和本地预览；不引入前端框架或运行时服务。构建脚本为 `node scripts/build.mjs`，`package.json` 暴露 `npm run build`；无须 npm 依赖即可复现。Pages workflow 只从经确认的版本标签部署。
- 列表页使用站点根 URL，详情使用 `?tool=<slug>`；用 History API 管理前进/后退，刷新详情也能恢复。无效 slug 显示站内错误并提供返回入口；避免需要服务端回退的深层路由。

## 主站信息架构

当前首页采用设计系统 V2：顶部 DPG 标识与 Design Playground 简介，下面以响应式网格直接展开全部已发布工具。桌面三列、中等宽度两列、窄屏一列，具体断点见 `DESIGN_SYSTEM.md`。每项展示 4:3 封面、名称、用途和标签，整卡可点击，顺序由 `tools.json` 决定。不设分类侧栏，不做分类分组、搜索或筛选，也不预留无功能的控件。工具较少时不做分页；零工具时显示清晰的空状态。

点击工具进入 `?tool=<slug>` 详情与运行页，展示名称、简介、返回全部工具与“独立打开”，主体为 iframe。同一时间只加载选中的工具，不在首页同时运行全部工具。小屏幕保持单栏，工具运行区优先占宽。标签、日期可作辅助信息，不作为筛选入口。卡片封面读取工具目录中的静态图片，默认 `assets/cover.png`；缺少配置时使用编号占位，不加载工具实时预览。

分类、搜索、筛选属于后续阶段，启用时另行确认需求，同步更新元数据、校验器和 QA。V1 不要求 `category` 字段；`tags` 可为空数组。设计系统中的通用控件规范不代表首页必须实现这些控件。

## 默认选择与待实例化数据

名称 DPG，公开仓库、`main`、GitHub Pages 项目站、纯静态架构、中性深色视觉与白色高亮、站内 iframe、独立打开均已确定。仓库、站点与工具数据从实际配置读取，不猜测。当前设计 token 与布局以 `DESIGN_SYSTEM.md` 的 V2 规范为准；历史发布和 QA 记录保留其对应版本的描述。

## 边界提醒

客户端沙箱是交互隔离，不等于安全隔离。公开站点不承载秘密。上传前确认素材使用权；自动文本扫描无法识别所有图片文字、压缩包或混淆内容，须有人眼复核。

## 发布与版本边界

功能分支承载开发，`main` 保持已审核的稳定状态。每次 push 前先完成风险检查并取得用户对具体提交与目标的明确确认；合并与上线也须明确授权。版本标识、发布记录和回退流程以 `GITHUB_WORKFLOW.md` 为准。`published` 表示纳入构建，不等于已上线。公开仓库中的 draft 源码同样公开，状态只控制站点构建。

公开源码仅包含通用规则与扫描器，具体敏感词库在仓库外本地维护，不随仓库或部署产物分发。公开 CI 的通用结构检查不能替代提交与推送前的私有内容检查；配置和阻断规则见 `CONTENT_POLICY.md`。
